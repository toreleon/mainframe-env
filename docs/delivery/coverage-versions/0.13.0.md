# mainframe-env 0.13.0 — Complete Db2 13 programming surface

Status: **Proposed**  
Start gate: 0.12 parser, binder, catalog, relational IR, and transaction contracts frozen  
Completion dependencies: 0.12.0  
Estimate: 24–36 engineer-months

## Outcome

Complete the pinned Db2 13 SQL and programming surface over the generic 0.12
engine, including advanced objects, routines, packages, locking, and recovery.

## Owned scope

- Complete all remaining rows among the 158 pinned statement headings and the
  pinned SQL PL statement/condition portfolio.
- Implement advanced query, merge, recursive, temporal, XML, LOB, array,
  sequence, generated, identity, materialized-query-table, and analytic behavior.
- Complete routines, triggers, transition data, modules, global variables,
  aliases/synonyms, advanced views, and object dependency/invalidation rules.
- Complete static/dynamic packages, plans, bind/rebind/free, privilege chains,
  isolation, locks, deadlocks, savepoints, logging, restart, and recovery.
- Cover the pinned distributed/database connectivity and administrative
  programming behavior without claiming whole Db2 operational parity.

## Work packages

| ID | Deliverable |

| DB2-1302 | Advanced query, temporal, XML/LOB/array, and analytic semantics |

## Parallelization

Advanced type/query, routine/trigger, package/plan, and lock/recovery cohorts can
run in parallel behind 0.12 contracts. Catalog mutation and dependency graph
updates have one owner; statement families may not introduce private catalogs.

0.13 can run alongside 0.10, 0.11, 0.14, and 0.15. Its final transaction and
recovery evidence becomes an input to 0.16.

## Exit gate

- 158/158 pinned SQL statement headings and the pinned SQL PL portfolio pass all
  applicable coverage gates with no partial row counted as complete.
- Advanced types/objects, routines, triggers, packages/plans, privileges,
  isolation, deadlock, logging, restart, distributed, and scale matrices pass.
- Catalog changes, invalidation, authorization, and rollback are atomic across
  every supported failure point.
- Licensed Db2 13 differentials pass for the complete pinned surface.
- The 0.12 common subset and CardDemo database behavior remain exact.

## Non-goals

- Db2 installation, physical access-path or storage-engine identity, and every
  administrative utility outside the pinned programming surface.
