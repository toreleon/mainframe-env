# mainframe-env 0.6

Status: Official `0.6.0` release prepared; not tagged, published, or deployed
by this branch

## Release scope

The 0.6 line adds typed dataset, catalog, allocation, locking, migration, and
recovery behavior for five primary VSAM organizations and the pinned 31-command
AMS surface. It includes keyed/RBA/RRN/sequential access, PDS/PDSE generations
and aliases, catalog routing, GDG lifecycle, AIX/PATH dependencies, CI/CA and
spanned geometry, atomic mixed mutation, SHAREOPTIONS, owner-scoped RLS locks,
KSDS TVS units of work, bounded IDCAMS parsing and MAXCC/LASTCC control,
authorization, snapshot flows, restart reconciliation, backup/restore, and
backward-readable MEDS1 through MEDS6 state.

Physical or installation-dependent operands retain explicit capability
conditions rather than generic success. The independent pure-state model and
its property/metamorphic and mutant checks are local assurance only.

## Parallel integration boundary

The 0.3 through 0.7 subsystem implementations were developed and integrated
in parallel before official product promotion. Consequently this taggable 0.6
source baseline already contains accepted later-minor JCL planner work. Its
presence does not expand the claims of the 0.6 release line.

## Differential limitations

The real licensed z/OS 3.2 dataset/VSAM/AMS campaign remains exactly 0/36
pending; the reference model cannot satisfy it. Enterprise COBOL remains
exactly 0/153, RACF/SAF remains exactly 0/48, and the JCL/JES2 licensed
differential remains pending where applicable. Simulations, generated output,
historical receipts, and CardDemo results grant no licensed IBM differential
credit.

## Release artifacts

The release retains deterministic, unpublished receipts for
`aarch64-apple-darwin` and `x86_64-unknown-linux-gnu`. Each receipt records the
locked Rust 1.98.0 build inputs, canonical path remapping, binaries,
configuration and migration identities, SBOM, provenance, and checksums bound
to the clean 0.6 source tree. All manifests retain `published=false`.
