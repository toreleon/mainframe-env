# mainframe-env 0.7

Status: Official `0.7.0` release prepared; not tagged, published, or deployed
by this branch

## Release scope

The 0.7 line adds the lossless bounded JCL frontend, generated statement and
parameter identities, catalog-driven validation, INCLUDE and procedure search,
symbol timing, overrides and backward references, immutable typed job plans,
capability annotations, and all 13 JES2 JECL forms. All 20 JCL statements, 74
DD parameters, 19 EXEC parameters, 35 JOB parameters, 76 OUTPUT parameters,
and 13 JECL statements are inventoried, recognized, and validated: 237/237
rows with 474 obligations and 711 typed cases.

This is a converter and planner release. JES scheduling, spool lifecycle, job
execution, utility runtime, and row-wide execution/condition/recovery claims
belong to later releases. Deferred entries remain explicit in the plan and
produce unsupported-capability diagnostics; they are not silently ignored or
misreported as executed.

## Parallel integration boundary

The 0.3 through 0.7 subsystem implementations were developed and integrated
in parallel before official product promotion. Each release commit advances
the same integrated tree and limits its claims to the corresponding minor; no
alternate product tree was reconstructed. This 0.7 release is the final state
of that linear promotion chain.

## Differential limitations

The JCL/JES2 licensed z/OS 3.2 differential remains pending because no pinned
licensed receipt was supplied. Enterprise COBOL remains exactly 0/153,
RACF/SAF remains exactly 0/48, and dataset/VSAM/AMS remains exactly 0/36.
Simulations, generated output, historical receipts, and CardDemo results grant
no licensed IBM differential credit.

## Reproduced CardDemo limitations

The current CD-006 and CD-013 evidence receipts are stale and are not accepted
as current passes. Reproduction found two independent product defects:

- fixed-format comment text leaks into a multi-receiver `MOVE` during online
  execution; and
- IDCAMS rejects CardDemo's `DELETE ... CLUSTER` syntax and its
  `DATA/INDEX(NAME(...))` component forms.

These defects cause the current CardDemo online and batch journeys to fail.
They are disclosed rather than repaired on this release-preparation branch,
and no gate or evidence rule is weakened to conceal them. Version 0.7.1 is the
planned corrective patch.

## Release artifacts

The release retains deterministic, unpublished receipts for
`aarch64-apple-darwin` and `x86_64-unknown-linux-gnu`. Each receipt records the
locked Rust 1.98.0 build inputs, canonical path remapping, binaries,
configuration and migration identities, SBOM, provenance, and checksums bound
to the clean 0.7 source tree. All manifests retain `published=false`.
