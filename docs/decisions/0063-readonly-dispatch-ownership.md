# 0063. Actual dispatch ownership for selected readonly effects

Status: proposed; implementation and focused controls unrun.
Owner: host, execution and CICS maintainers
Scope: original compiled dataset READ and CICS file read/browse intent/result attribution
Applies from: mainframe-env selected typed nonmutating dispatch occurrences

The existing EffectRecord describes coordinator-owned host dispatch, distinct from participant mutation/UOW state. Its canonical request/result, original actor/run/attempt, capability/resource audit metadata, immutable occurrence key and recovery fence also describe a readonly occurrence. Keep is_mutating and explicit nested Mutation unchanged. A separate typed selection requests original keys for DatasetRequest::Read and CICS file-read operations, using the existing invocation-key and effect-sequence allocation. Other readonly host families remain unchanged.

The actual coordinator journals the intent before the scoped provider and the actual reply/audit after it. If result persistence fails after a keyed readonly dispatch, retain the real intent and report UnknownOutcome. Do not manufacture an EffectRecord from an audit, trace or returned screen. Intent/Unknown recovery remains bounded, leased and authoritative; it never redispatches the original effect to resolve uncertainty.

CICS retains the actual selected readonly reply in the existing version-three canonical envelope after ordinary command execution. This supplies ownership evidence, not proof that an old cursor is live. An exact readonly duplicate validates full retained identity and refuses UnknownOutcome. Repeat the lookup after exclusive CommandLease acquisition so an initial miss cannot redispatch after a competing command completed; a postdispatch duplicate/conflict also never admits a cached readonly reply. Existing mutation replay and unkeyed compatibility calls remain unchanged.

Dataset READ carries explicit bounded dataset, key, member and record-count operands; it does not consume a provider browse cursor. Existing resumable scoped dispatch still requires an actual response with the identical canonical result digest before machine progress. CICS browse state is volatile: this slice does not reconstruct it. Midbrowse process recovery needs a separate local cursor ownership design. The existing source route that closes ENDBR before RETURN can retain all completed command records and subsequently reach the ordinary genuine no-input RECEIVE and existing MEOM4 suspension handoff.

No Machine/store codec, clock, generation, capability, SAF, cancellation/deadline or quota contract changes. Added records consume existing bounded stores and retention rules. Full source oracles and original acceptance counts remain unchanged. No application strings or raw customer data enter production code or repository fixtures.
