# 0064. Owned local application composition

Status: proposed; implementation and controls unrun
Owner: application package, dataset and CICS maintainers
Scope: finite local signed-content selection through one shared provider-state store
Applies from: mainframe-env owned local application composition profile

The local publisher stages an ordinary signed application generation, validates its complete retained package, and prepares the actual dataset seed and CICS definition owners before selecting it. Preparation holds the CICS owner before the dataset owner, matching the existing file-dispatch direction. Live tasks, cursor, lock and unit owners refuse this publication. Program and transaction catalogs stay held with the installer and publication owners until acknowledgement and cache publication finish.

The participating program payloads, explicit BMS and FILE codec bytes, transaction target bytes and full raw seed inputs must equal the signed Program, Resource and Data entries. Transactions use Resource paths `transaction/<normalized-name>` with their exact normalized program target as the payload. The Resource entry `seed/snapshot` contains the exact SHA-256 reference of the original full seed snapshot codec, authenticating attributes and geometry alongside the Data entries' raw bytes. The ordinary artifact admission contract remains authoritative. Every Program, Resource and Data entry participates, and duplicate, missing, foreign or orphan definitions refuse. Source entries now participate through complete signed raw-file dependency closures and an actual bounded CobolCompiler Executable request. Every offered program must equal the entire real publisher result, including payload, content reference, current manifest and semantic identity. The full immutable SourceBundle is passed unchanged: its SourceId covers logical paths, format, encoding, options, provenance and ordered COPY libraries. Actual SourceIds are retained in the local binding and receipt, and exact retry must reproduce them. The finite first-party profile now requires one generic signed Resource at `source-commitment/{NORMALIZED_PROGRAM}` and a direct Program dependency on it. Its compact canonical JSON, in declared field order, is `{contract,program,source_id,mode,target,options,source_entries}`: contract is `mainframe-env.application-local-source-commitment@1`, mode is `executable`, SourceId is the actual lowercase 64-hex identity, and options/source_entries use sorted BTreeMap order. The Resource dependency vector is the sorted exact mapped Source-entry set. Its existing manifest byte count, SHA-256, dependency graph and package signature authenticate the full declaration. The actual immutable SourceId commits primary identity, every logical file path/raw byte/format/encoding, Source options, provenance and ordered COPY libraries. The remaining fields commit the exact target, CompilerRequest options and logical-file-to-signed-entry mapping; a same-MIR provenance change or a publisher-equivalent request-option change therefore cannot borrow an earlier signed commitment. Verification compares complete canonical bytes before compilation and charges the canonical copy within the unchanged source/seed/program budget. The API provides prospective Resource path/bytes for genuine package signing, not an authority token. This identity commitment closes finite metadata admission while package-only reconstruction remains unavailable: the caller still supplies the typed immutable SourceBundle/request matching the signed identity. No IBM ABI, vendor compilation equivalence or arbitrary subsystem/global completeness is inferred. Profile and Migration entries remain verified retained content; this profile does not execute migrations or apply an external security profile. Subsystem sections without a genuine held preparation are unsupported here. The full application acceptance contract remains unchanged.

Provider preparation retains the actual codecs, geometry, limits and expected row versions. The seed binding additionally covers the complete retained seed snapshot, including attributes, and not just its existing raw content identity. One call to the existing `put_provider_states_atomic` commits those rows, the actual isolated next installer state, the full local static binding and the retained generation binding. A nonserializable acknowledgement is created only after successful atomic return; each still-held provider checks its exact writes and the same store Arc before changing a cache. No sequential fallback, readback-as-acknowledgement, IssueObservation or complete flag supplies this authority.

The new seed preparation refuses any planned dataset named by another currently selected package, including an empty dataset whose attributes still equal the offered seed. This check precedes the current package's exact-retry return; missing or ambiguous selected generation authority refuses. Retained but currently unselected generations do not independently claim dataset names. The actual held state is joined to bounded selection, retained-generation and dataset observations, including exact versions and canonical payloads of participating rows. Namespace counts retain their existing DatasetLimits caps; a single overflow-probe row detects truncation and never grants an extra accepted owner. Observation bytes plus a canonical comparison copy are charged to the existing 64 MiB composition budget. Large retained histories can therefore refuse this new finite profile; legacy seed install/selection remains unchanged. These observations grant no acknowledgement or exclusion of trusted direct store writers.

A successful exact retry preserves runtime-edited seed records and their versions. Upgrade and rollback require the same owned static key set; rollback supplies the full original signed definitions and seed snapshot and joins the retained real Ready generation. Opening revalidates all selected static rows, the selected seed generation and full snapshot, and the actual Ready installer generation. Orphan generation or partial selection records refuse opening. A backend infrastructure or poisoned-lock return during the atomic call fences the live application, CICS and dataset owners as Unknown until an authoritative reopen. An actual committed-but-unknown call may become valid after that reopen; the failed live call does not gain successful acknowledgement.

The finite composition profile charges a 64 MiB payload-copy budget and retains all existing store and provider limits. It makes no aggregate process-memory measurement claim. Raw store writers and direct provider administration remain trusted embedding responsibilities; this single-process owner does not supply distributed exclusion or certify arbitrary manual retries. Existing publication paths for packages outside this profile remain available, while legacy selection and online installation cannot replace this profile's selected package or overlapping routes.

Proposed real Memory and SQLite controls cover full raw seed records, signed route bytes, selected static rows, exact retry, upgrade, retained rollback, reopening, capacity refusal, foreign acknowledgement, missing/corrupt state, and actual before/after atomic-return fault injection. They remain unformatted, uncompiled and unrun. This proposal supplies no Foundation, CD009, CD016, journey, vendor, licensed or oracle acceptance credit; the original full V3, package and seed owners, reopen comparisons, rollback requirements and original limits remain required.
