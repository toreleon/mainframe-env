# mainframe-env 0.8.2

Status: Official `0.8.2` patch release

## 0.8.2 distribution patch

0.8.2 preserves the supported runtime and contract surface of 0.8.1. It adds a
release-time offline Cargo vendor bundle for the exact locked dependency graph,
publishes a SHA-256 checksum for that bundle, and verifies the vendored
workspace with `cargo build --workspace --all-features --locked --offline`
before publication.

The runtime corrections and compatibility policy inherited from 0.8.1 are
recorded below.

## 0.8.1 patch corrections

0.8.1 resolves every finding from the
[0.8.0 JES2 review](../delivery/coverage-versions/review/0.8.0.md):

- warm restart reconstructs prior abends before evaluating later conditions
  and reuses the original per-step idempotency-key range;
- utilities receive exact typed dataset records, preserving empty records and
  embedded newline-valued bytes;
- allocation reserves absent dataset names before the existence probe and
  create, and DD cleanup failure no longer reclassifies the original abend;
- omitted abnormal `DISP`, EBCDIC fixed-record padding, negative zoned edits,
  content-addressed spool rollback, JES queue classification, de-hardcoding
  coverage, and local artifact hygiene are corrected.

The optional durable replay-base metadata defaults safely for existing data.
0.8.1 accepts 0.8.0 checkpoint identities; an in-flight 0.8.0 step without
enough metadata for safe replay fails closed and can be resubmitted rather than
risk duplicating a committed effect.

## 0.8.1 runtime scope

The 0.8 line executes immutable typed JCL plans through deterministic JES2
lifecycle semantics. It adds bounded class and initiator scheduling, per-step
state and condition handling, DD allocation and complete DISP processing,
ordered concatenation, temporary and generation data resolution, artifact-
backed spool, output routing and retention, started tasks, internal readers,
bounded NJE/MAS topology, SAF-checked operator controls, and durable restart,
cancellation, overload, backup/restore, migration, and unknown-outcome
handling.

Execution resolves each step once into an admission-pinned typed registration.
All nine required utility families have real bounded effects; unsupported
controls fail explicitly. Runtime behavior does not dispatch on conformance row
identities or fall back to summary-only or generic success.
