# 0060. Optional passive CICS READ copyback observation

Status: proposed. This is an infrastructure observation contract, not subsystem semantic or acceptance completion.
Owner: CICS runtime, interpreter and privileged Rust embedding maintainers
Scope: optional passive equal-width successful READ storage postimage assurance observation
Applies from: mainframe-env optional assurance-observers infrastructure profile

The ordinary host receipt is recorded before a language runtime applies INTO, RESP and EIB. A subsequent SEND or RETURN can overwrite those cells, and ordinary CICS RETURN has no installed-program completion-checkpoint witness. Terminal fields, host digests or a later checkpoint therefore cannot attest an earlier READ storage postimage.

An explicit `assurance-observers` feature adds a volatile bounded ReferenceMachine collector and an opaque same-server ProductServer manager. Both are default off. The privileged embedding registers a structural plan containing actual resolved `CicsStorageSlot` references and dimensions, with asserted selector/principal/artifact/semantic/source identity. No application program, principal, record or file name is a production exception. The conformance owner supplies its independently source-grounded selections and bytes; those expected bytes never enter runtime capture.

The collector has no callback, external synchronization, I/O or extra drive. It captures actual raw static storage views and six actual implicit EIB Bytes/Decimal cells only after response-state write, payload projection and `finish` succeed, before later drive. Legacy/unbound slots, unknown or failed application, non-NORMAL results, extra/missing/reordered READs, changed views, restoration and diagnostic bounds latch incomplete state. Ordinary execution behavior and existing grant, actor, SAF, cancellation, generation, deadline, unknown, quantum and storage controls remain the owners of admission and execution.

The plan permits at most 64 READs, 16 selected cells per occurrence, 64 KiB captured payload and 64 KiB explicitly charged identity metadata. The server reads at most 512 actor audit rows and 1024 lifecycle events, requesting one additional row to detect an incomplete page. No truncation, eviction, fabricated empty success or recovery fallback produces a witness. The original runtime/storage/event/quantum budgets are unchanged.

READ is normally nonmutating and has no core EffectRecord. Each observation binds its opaque actual offered origin, sequence and canonical request/result identities to exact actor-specific Success audits and ordered EffectIntent/EffectResult event pairs. The finalizer separately verifies the actual RETURN core/Terminal replay receipt and current exact ordinary Completed event/actor/artifact, with no owner/recovery lease. Provider retention resolution and actor-event ticks are checked in their own domains. Nested dataset evidence remains separately required from the first-party owner.

Only the actual ProductServer machine-construction path binds an arm; only its ordinary-completion path, after all original cleanup succeeds, can expose a completed archive. Registry locks cover selection only, never callbacks, providers, clocks, store reads, drive or cleanup. Any earlier failure drops the internal binding into a fixed diagnostic refusal. Caller assertions, copied rows or checkpoints cannot construct the opaque completion value. The final store observations are bounded and non-atomic; they are not a durable owner lease or permission to redispatch, retire, recover, delete or publish cached replies.

The archive is private in memory within the owned fixture. There is no new HTTP endpoint, trace schema, provider capability, replay namespace, Machine trait method or checkpoint codec. No raw customer/credential bytes or archive instances enter Git or public logs. Read-only access to selected postimages is restricted to the privileged Rust embedding; the assurance owner must preserve privacy, source binding, producer cleanup and independent expected-byte inputs. A future durable/export archive needs a separate storage, encryption, retention and owned-I/O decision.

Pinned offline READ, common options, EIB and function-code bodies ground the observation targets. They provide no licensed execution evidence. Equal-width successful reads are the initial owner scope; generic longer-area padding, negative conditions, raw MDT, browse copyback, handlers, IBM COBOL numeric/COMP semantics and full result-storage acceptance remain pending. The unavailable original COBOL publication body is reported rather than replaced by a local fixture.
