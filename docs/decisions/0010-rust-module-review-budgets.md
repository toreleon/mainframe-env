# ADR-0010: Enforce Rust module review budgets and stable split boundaries

Status: **Accepted by repository owner**
Owner: **architecture maintainers**
Scope: **Rust production-module size, crate facades, generated sources, and CICS family growth**
Applies from: **mainframe-env 0.9.0 development**
Supersedes: **the soft 800–1,200-line review trigger in the architecture overview and implementation prompt**

## Context

The former maintainability guidance asked for review at roughly 800–1,200
lines, but did not fail any gate. Several files accumulated multiple reasons to
change and thousands of production lines. Inline test suites made raw file
length a poor proxy, while two crate roots accumulated implementation despite
the facade-only `lib.rs` rule.

The complete 263-command CICS program would amplify the problem if command
descriptions and semantics were appended to the existing pilot service. A
mechanical rule must stop new debt without forcing arbitrary, behavior-changing
splits of every legacy module in one release.

## Decision

The soft trigger is replaced by a **hard limit of 1,200 physical production
lines** for every new or non-exempt Rust module below `crates/`.

The machine authority is
[`conformance/0.9/inventory/module-budgets.json`](../../conformance/0.9/inventory/module-budgets.json).
`python3 -B tools/check_module_boundaries.py` validates that inventory and is a
blocking part of `cargo xtask architecture-fast --check`.

The recorded ceilings are the final pre-adoption baseline after the other
pre-0.9 review fixes, including their bounded retention and readiness work.
The one-time `--refresh` used to adopt this decision therefore captures that
integrated state. Any later increase requires a superseding decision; an
ordinary feature or repair may only preserve, lower, or remove a ceiling.

### Counting and exemptions

- A production-line count includes blank lines, comments, attributes, and test
  helpers compiled or declared before the terminal unit-test section. This is
  deliberately conservative.
- A top-level `#[cfg(test)] mod ...` begins an inline test-only suffix. Files in
  Cargo `tests/` and `benches/` directories are test-only and do not consume a
  production-module budget. Large scenarios belong in those files or focused
  conformance modules, not inside production implementations.
- Existing non-generated modules above 1,200 lines have an **exact,
  non-growing ceiling** equal to their accepted production count. Each
  inventory row records its current responsibility and a stable split boundary.
  Any count change fails until the reviewed inventory is refreshed; a split
  lowers or removes the ceiling. Raising a post-adoption ceiling requires a
  superseding ADR, not an ordinary inventory edit.
- Generator-owned Rust files live under a `generated/` directory and begin
  with `// @generated by`. A generated file above 1,200 lines has its own exact
  ceiling, generator command, and readable normative authorities in the
  inventory. A hand-maintained file named `generated.rs` is not generator-owned
  merely because of its name.
- `python3 -B tools/check_module_boundaries.py --refresh` updates counts while
  preserving human-written rationale. It exists for the final pre-adoption
  rebase and for lowering ceilings after splits; it cannot invent a rationale
  for a new exemption.

### Crate facades

Every `src/lib.rs` is a crate facade. It may contain crate documentation,
attributes, module declarations, public re-exports, and small contract identity
constants, but not functions, data types, traits, implementations, private
imports, or macros. The application and conformance crate roots are facades in
the accepted 0.9 candidate.

The checker discovered one earlier exception in
`mainframe-env-coverage/src/lib.rs`. Its exact count and stable extraction
boundary are recorded as non-growing debt. No other facade exception is
permitted, and that row disappears when the ledger model moves to its own
module.

### CICS 0.9 family layout

The existing CICS `service.rs` pilot is frozen at its exact accepted production
count. The 263-command expansion may not append command descriptions or new
semantic families to that monolith.

Before the module gate passes, the CICS provider must contain both:

1. at least one generator-owned descriptor module under `src/generated/`; and
2. the exact seven reviewed semantic family modules under `src/handlers/`
   declared by the frozen command catalog.

New CICS Rust modules outside the accepted `abi.rs`, `lib.rs`, `retention.rs`,
and `service.rs` set must live in one of those two layers. The pre-adoption
`retention.rs` module is a provider-lifecycle codec and dependency boundary,
not a command-description or command-semantics family. Descriptor modules have
a readable catalog/schema authority and contain no handwritten behavior. The
task, time, program, terminal, file, queue, recovery, interval, storage, and
journal handler modules contain
reviewed semantics, are never generated, and remain subject to the 1,200-line
hard limit. This establishes the layout before CIC-901 adds broad families
rather than promising a later cleanup.

### Amendment: journal-control family (2026-09-23)

The reviewed CICS handler inventory now includes
`handlers/journal_control.rs`. It owns one bounded durable named-journal
authority for WAIT/WRITE command slices; it does not add a crate, provider,
dispatch bypass, condition authority, or second state owner. The readable
typed-execution registration declares `journal-control`, the descriptor
generator emits its route, and `module-budgets.json` admits the module under the unchanged
1,200-production-line limit. This amendment is limited to that family boundary
and does not authorize rows that remain unready.

### Amendment: security-control family (2026-09-23)

The reviewed handler inventory includes `handlers/security_control.rs` and its
bounded `authority.rs` child. CICS owns command-shape, task-context, and
EIB/condition translation, while the server binds the accepted RACF/SAF
authority through one narrow interface. The family adds no security database
or credential store. The descriptor generator admits `security-control` only
for individually registered rows, and the exact protected service root ceiling
is unchanged. Both handler modules retain the ordinary 1,200-line limit.

## Consequences

- `architecture-fast` now fails on a new oversized module, an expanded legacy
  ceiling, a stale exemption, a generator without provenance, implementation in
  a new crate facade, or CICS growth outside the descriptor/handler split.
- The inventory makes legacy debt explicit without treating arbitrary line
  slices as sound architecture. Splits follow parsing, validation, transition,
  persistence, recovery, or command-family reasons to change.
- Moving tests can reduce production counts but cannot disguise production
  behavior as tests; only Cargo test-only paths and a terminal top-level test
  module are excluded.
- Generated expansion remains reviewable through its normative source and
  exact generated ceiling rather than forcing mechanically produced rows into
  handwritten modules.
