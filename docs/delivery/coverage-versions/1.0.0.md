# mainframe-env 1.0.0 — Stable pinned programming-surface release

Status: **Proposed release gate**
Start gate: 0.17 certification passes on the exact release candidate
Completion dependencies: 0.17.0
Estimate: release gate; no feature-development budget

## Outcome

Promote the certified candidate as the stable 1.0 implementation of the pinned
IBM programming surface, with truthful scope, reproducible artifacts, and a
tested upgrade and rollback path.

## Owned scope

- Freeze the exact source, dependency graph, generated catalogs, baseline
  receipts, durable-state schemas, migrations, profiles, and release metadata.
- Publish precise supported-surface and exclusion statements with numerator and
  denominator evidence; do not broaden the claim to whole-product parity.
- Produce signed/reproducible artifacts, SBOM, provenance, checksums, release
  notes, upgrade/rollback instructions, operational limits, and support policy.
- Execute the final clean-tree build, install/upgrade, smoke, rollback, and
  artifact verification from the same candidate certified in 0.17.
- Tag, publish, deploy, or push remotely only with explicit user authorization.

## Release work packages

| ID | Deliverable |
|---|---|
| REL-1001 | Version, changelog, support/exclusion, migration, and rollback freeze |
| REL-1002 | Reproducible artifacts, SBOM, provenance, signatures, and checksums |
| REL-1003 | Clean install/upgrade/smoke/rollback and artifact verification |
| REL-1004 | Final evidence manifest and independent release approval |
| REL-1005 | Authorized tag/publication/deployment and post-release verification |

## Certification handoff

Prepare and freeze REL-1001 metadata before the terminal CER-1706 rehearsal in
[0.17](0.17.0.md#early-harness-inputs-and-exact-candidate-handoff). This early
preparation does not authorize release or claim REL-1001 complete before its
acceptance conditions pass. At promotion, verify the already-certified source,
metadata and artifact identities rather than making an untested version or
changelog edit after certification. Any changed candidate input invalidates
affected 0.17 receipts under existing policy; no receipt may be silently relabeled.
Final promotion still waits for the complete 0.17 gate and separate authorization.

## Parallelization

Documentation, artifact assembly, SBOM/provenance, and staging validation can
prepare in parallel against the frozen candidate. They must all converge on the
same source and artifact digests. Candidate mutation restarts affected 0.17
certification; final promotion is deliberately serialized.

## Exit gate

- The 0.17 candidate source, generated catalogs, evidence manifest, and released
  artifacts have matching, recorded identities.
- Clean install, supported upgrade, backup/restore, rollback, and smoke tests
  pass using only published inputs and instructions.
- Supported and excluded scopes, limitations, compatibility, and security
  posture are explicit and match the machine-readable inventory.
- Reproducibility, SBOM, provenance, signatures/checksums, licensing, and
  advisory gates pass.
- Tag/publication/deployment occurs only after explicit authorization and is
  followed by artifact and endpoint verification.

## Non-goals

- Adding features or accepting a last-minute compatibility exception during
  release promotion.
- Claiming full z/OS or whole IBM product parity.
