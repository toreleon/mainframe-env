# ADR 0058: Explicit protected native MQ scope succession

Status: proposed, unexecuted
Owner: configured COBOL root driver, selected MQ authority and store adapters
Scope: explicit protected-scope successor of one manager-held fenced native MQ root
Applies from: mainframe-env explicit native MQ custody and protected-scope succession profile

## Boundary and first profile

ADR 0034 remains the admission and compiled root terminal publication authority.
ADR 0057 adds an explicit manager cutoff of one actual live Open root. An unknown
exit does not choose an MQ unit commit/backout, successful return, new CALL reply,
or source-known task end. This additive profile can create a distinct actual
compiled parentNone successor only after the manager possesses the old service,
configured clock, physical store, original root and closed cutoff observation.

The manager constructs a genuinely new selected MQ service from the same actual
retained store Arc, authorizer Arc, generation/fence and original finite limits.
Its clock reads the same configured clock's explicit callback-free custody view;
no copied clock tick, global time change or recursive original hook is used.
Public application envelopes, copied RootDriverClaims, equal identifiers,
reopened filenames and recovered JSON rows cannot construct this manager proof.
The root router still checks exact store/provider/control Arcs and catalog,
installed compiled artifact, semantic/manifest/content identity and original
grants/context. The coordinator constructs one fresh actual Admitted execution,
event and outbox row before its borrowed admission hook is produced.

Memory and SQLite support the storage transaction. Other stores refuse by
default. The actual old fenced row, version1 custody marker, complete actor/core
and provider observation, ownership indexes, full effect audits and cutoff
physical epoch must still match under the sole lock/writer transaction. A fresh
root/run is required, with the same principal and original current tick/deadline
rules. New root, actor, run and exact-row indexes are newly admitted at version1;
each transferred namespace scope CAS advances its actual old version by exactly
one. The new ownership document uses version2 and records every exact namespace
scope version. Version1 serialization and actor/run/exact-row index rules remain
unchanged. Claim validation binds the scope version map to the actual inserted
document; this is not a generic acceptance of scope versions greater than one.

The old root remains Uncertain, with all old actors, events, effects, effect
audits, outbox, invocation/attempt/catalog and represented unknown work retained.
An explicit custody-successor marker at version2 records the new admitted root.
This neither rewrites the old root as Terminal nor confers old effect/CALL reply
or original old unit disposition authority. All old volatile gates remain
irreversibly revoked; no old service or frame is activated again.

## Unknown-row protection

A broad transferred namespace alone would permit a successor to overwrite old
unknown work. The same transaction therefore installs immutable physical fences
on every represented old provider row and absent exact identity. Puts, deletes, renames, attributed writes
and root terminal publication all consult those fences. Old units, messages,
pending/final/cursor rows, receipts, handles, replay and CALL rows cannot be
rewritten, including an unchanged-payload version bump. Public provider-retention
archive/delete and aggregate/capacity replacement paths check the same physical
pins before archive insertion or mutation under their original lock/transaction.
A separately supplied terminal owner does not permit archiving a pinned unknown
row; original provider validation, dependencies, epochs and quotas still apply.
Independent controls retain unpinned archive behavior and refuse a foreign
terminal-owner graph for pinned MQ replay/CALL protocol rows, preserving complete
raw state, archive contents/usage and the genuinely uncertain predecessor.

The actual selected MQ source derives precisely four infrastructure identities:
selected control, rich manifest, rich catalog, delivery metadata. The existing
control codec already validates its new incarnation/allocation successors; that
one row is governed by the new exact scope owner. The other three allow only an
exact same-payload CAS. The selected publication source always pins rich catalog
and manifest bytes; delivery row delta always includes its metadata CAS even
when member bytes do not change. This first connection-only profile retains the
delivery metadata payload and refuses work that would change that aggregate.
It adds no queue/unit disposition, MQ return code, language or participant rule.

Pin payloads are bounded to4096 before JSON Value/string allocation, including
legal escaped controls and conservative non-ASCII identity bytes. The complete
encoded payload is checked again; the short ASCII MQ codec bytes are unchanged.
Legal control-byte identity max/+1 and over-codec cases require whole-store
refusal before a fresh owner can hold an unusable pin.

The aggregate includes the retained cutoff fenced row and version1 marker,
before proposed admission/fence rows are added. All captures, proposed rows and
admission/fence changes consume the existing
256 actor, 4096 operation and 64 MiB ceilings. The successor transaction charges
all retained predecessor actors plus its one fresh root admission against256;
the existing individual-root enrollment guard remains unchanged. Structural
255/256 predecessor controls isolate literal aggregate256/257, and the over-limit
request must refuse with whole-store equality. They do not attest enrollment.
Refusal does not widen quotas,
drop rows, shorten deadlines or retry an unchanged request. A transaction failure
returns no successful admission; a lost acknowledgement does not mint a native
proof or trigger an automatic retry. Dedicated lost-ack reconciliation remains
outside this first profile.

## Independent controls and remaining acceptance

Unrun Memory/owned-SQLite controls compare actual complete old core/provider
records, exact versioned indexes and fresh admitted state; they refuse corrupted
marker/epoch/version/actor, foreign principal/run/root/scope, missing dependencies,
old writers, new writers to unknown or absent rows, changed immutable pins, delete/rename
and repeat admission with whole-storage equality on failure. Source-derived new
compiled MQNEXT calls compiled MQCOLD with an actual OUTCOME argument, preserving
the original live Open clock phase in a separate test. Its oracle requires actual
Completed output/reply bytes, fresh root/child ownership, exactly one old and one
new CONNECT, unchanged old core/unknown rows, retained old Uncertain root and no
MqQueue SAF observation. The persisted source-defined cold registry epoch must
advance by exactly1 while generation/fence remain unchanged. After the revoked
original drive returns Unknown, old core, fenced root, exact2 receipts and physical
provider epoch must remain unchanged. It earns no execution credit until run.

The historical source05 cold-test source and failure remain retained. That input
has a handwritten outer caller and physically reopens SQLite by filename;
neither supplies this closed manager/compiled root proof. This additive control
does not relabel that historical failure as pass or weaken its acceptance.
Actual pending PUT/full removed GET and lost-ack/crash controls, physical SQLite
reopen custody, repeated successor recovery, source-complete IBM MQ9.4MQI and
COBOL6.5 publication bodies and original cold acceptance remain pending. A fresh
SQLite pool opened from a URL has no same-file ownership proof in the current
typed adapter; a closed owned file/connection reopen boundary is needed before
that producer can receive physical-reopen credit. Matching IDs or file paths do
not resolve that authority gap. These pending proofs are not a design-only stop
for the implemented same-store prerequisite.
