## Decisions and risks

- JCL remains the owner of fixed columns, continuation, in-stream data,
  symbols, procedure search/overrides, backward references, and JECL timing.
- The converter will reuse source/provenance and diagnostic contracts and will
  expose an owned immutable job-plan model; it will not introduce a generic
  parser framework or subsystem-local Conformance IR.
- Catalog-derived statement and parameter identities will drive validation,
  documentation, coverage bindings, and planner-closure checks.
- DD allocation vocabulary must remain compatible with the 0.6 lane. If an
  additive shared vocabulary change proves necessary, this lane will stop and
  report it before editing the shared boundary.
- Licensed IBM differential results cannot be fabricated. Differential
  obligations remain pending unless a pinned licensed oracle receipt is
  available; converter recognition/validation and independently reviewed
  golden/property comparison still form part of JCL-706.

## Controller review 1 repairs

The first controller review is closed in one focused repair. Every generated
fixture now carries its catalog-derived family, official row ID, keyword,
support state, capability, and target source line. Recognition requires that
exact row in the typed parser output. Validation requires the same row in the
immutable plan plus its exact typed node and, where applicable, matching
capability and support state. Mutation tests remove statement, JECL, and
parameter targets while leaving JOB/EXEC scaffolding valid and prove both
positive observations fail.

All 20 JCL statement malformed fixtures now contain reviewed target-specific
invalid forms and expected diagnostics. A malformed verdict passes only when
the expected code overlaps the target record; an unrelated malformed record
cannot satisfy it. IF validation rejects malformed operators explicitly.

The fixed byte-column projection now retreats to a UTF-8 character boundary
before slicing while retaining the original 72-byte ASCII semantics. Custom
delimited and CNTL data regressions place a multibyte character across byte
column 72 and prove exact lossless preservation, bounded behavior, delimiter or
ENDCNTL recovery, and following-statement recovery without panic.
