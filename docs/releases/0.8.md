# mainframe-env 0.8.2

Status: Official `0.8.2` patch release

## 0.8.2 runtime, storage, and distribution hardening

0.8.2 includes the post-0.8.1 fixes shipped in #47, #48, #49, #50, #51, #52,
#53, and #55, plus the #56 benchmark work. Installed COBOL programs now retain
ordinary state within a run unit, observe live cancellation and deadlines,
preserve unknown outcomes,
and use durable child journals with stable at-most-once replay identities.
Executable lowering now requires verified HIR. DCOLLECT rejects incomplete or
changing catalog traversals; provider-state Move uses one validated contract
across memory, SQLite, and PostgreSQL. Dataset evidence separates observation
perturbations from behavioral mutants, and the release adds an opt-in
memory-store scaling benchmark.

The tag also publishes a locked offline Cargo vendor archive and SHA-256,
verified by an offline workspace build.

### 0.8.2 compatibility

This patch changes supported runtime and contract behavior. Custom `WorkStore`
implementations must add `get_work`. Legacy MIR must be recompiled, and
protocol-1 or counter-era in-flight installed calls must be drained or
explicitly reconciled before protocol 2. Unknown effects remain in doubt
instead of entering ordinary COBOL exception handling; DCOLLECT may now fail
where 0.8.1 emitted partial output. Provider Move now reports missing memory
sources as `Conflict` and oversized SQL payloads as `PayloadTooLarge`. Current
dataset certification receipts use schema `@2`.

No automatic state migration, exactly-once guarantee, capacity certification,
or licensed-equivalence claim is added.

### 0.8.2 published assets

0.8.2 published the source vendor bundle and checksum. It did not publish 0.8.2
native binaries or native-binary receipts. The checked-in 0.8.1 target receipts
remain historical 0.8.1 evidence and grant zero 0.8.2 runtime-artifact credit.
The exact tag, Cargo.lock, asset digests, and successful historical offline-build
job are recorded in `release/0.8.2/source-distribution.json`.

The 0.8.1 release record below remains the prior baseline; it is not evidence
for the 0.8.2 runtime changes.

## 0.8.1 patch corrections

0.8.1 resolves every finding from the
[0.8.0 JES2 review](../delivery/coverage-versions/review/0.8.0.md):

- warm restart reconstructs prior abends before evaluating later conditions
  and reuses the original per-step idempotency-key range;
- utilities receive exact typed dataset records, preserving empty records and
  embedded newline-valued bytes;
- allocation reserves absent dataset names before the existence probe and
  create, and DD cleanup failure no longer reclassifies the original abend;
- omitted abnormal `DISP`, EBCDIC fixed-record padding, negative zoned edits,
  content-addressed spool rollback, JES queue classification, de-hardcoding
  coverage, and local artifact hygiene are corrected.

The optional durable replay-base metadata defaults safely for existing data.
0.8.1 accepts 0.8.0 checkpoint identities; an in-flight 0.8.0 step without
enough metadata for safe replay fails closed and can be resubmitted rather than
risk duplicating a committed effect.

## 0.8.1 runtime scope

The 0.8 line executes immutable typed JCL plans through deterministic JES2
lifecycle semantics. It adds bounded class and initiator scheduling, per-step
state and condition handling, DD allocation and complete DISP processing,
ordered concatenation, temporary and generation data resolution, artifact-
backed spool, output routing and retention, started tasks, internal readers,
bounded NJE/MAS topology, SAF-checked operator controls, and durable restart,
cancellation, overload, backup/restore, migration, and unknown-outcome
handling.

Execution resolves each step once into an admission-pinned typed registration.
All nine required utility families have real bounded effects; unsupported
controls fail explicitly. Runtime behavior does not dispatch on conformance row
identities or fall back to summary-only or generic success.
